## 宿題

- 取り組んだレベル：実装
- 使ったモデル：gemini-3.5-flash-lite（既定）
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加した（`uv run python -m app.ask --chat`）。空行か `exit` で終了する。
  - 会話履歴は `types.Content`（role が user / model）のリストとして自分で保持し、質問のたびに「これまでの履歴＋今回の質問」をまとめて `generate_content` に送るようにした。SDK の `client.chats` でも実現できるが、何を送っているかがコードで見えるようにするため、あえてリストで書いた。
  - API エラー（429・503 など）が起きたターンは履歴に残さず、次の質問を受け付ける。
  - 演習の TODO だったトークン数表示を共通関数にし、会話モードでも毎ターン表示するようにした。
  - `tests/test_ask.py` を追加した。偽のクライアントを使い、API を呼ばずに「2ターン目のリクエストに1ターン目の質問と回答が含まれる」ことを確認する。`uv run pytest -q` は12件すべて通過。
  - 実行環境は Codespaces ではなくローカル PC。API キーは `.env`（`.gitignore` 済み）に置き、`uv run --env-file .env ...` で読み込んだ。
- 結果：
  - 会話モードで「私の名前は長屋です。好きな食べ物はカレーです。」と伝えたあと「私の名前と好きな食べ物は何でしたか？」と聞くと、「長屋」「カレー」と正しく答えた。
  - 同じ2つ目の質問を従来の単発モードで聞くと、「これが初めての会話なので知りません」と答えた。履歴を送らなければモデルは前の発言を覚えていないことを確認できた。
  - 「LoRAとは？」→「メリットを2つ」→「さっきの2つ目をもう少し詳しく」の3ターンでも、「2つ目」が何を指すかを正しく理解して答えた。
  - 入力トークン数はターンごとに 11 → 74 → 205 と増えた。毎回履歴全体を送り直しているためである。
- 気づき・疑問：
  - LLM の API はステートレスで、「会話を覚えている」ように見えるのはクライアント側が履歴を毎回送っているからだと、実装して実感した。
  - 会話が長くなると入力トークンが増え続けるので、料金や無料枠、コンテキスト長の上限に影響するはず。長い会話では古い履歴を削る・要約するなどの工夫が必要になりそう（今回は未実装）。
